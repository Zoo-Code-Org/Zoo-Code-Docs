# Zoo Code 3.98.2 Release Notes (2026-11-23)

This snap patch release ships the Gemini model additions that missed the v3.98.1 release, adds opt-in Responses API support for OpenAI Compatible providers, and fixes three provider reliability bugs. The Zoo Pass preview promo is also shown again in the release announcement.

## Gemini 3.8 Flash and Gemini 4 Carbon, Hydrogen, and Neon

Zoo Code adds four new Gemini models to the model catalog: [Gemini 3.8 Flash](https://aistudio.google.com/docs/models/gemini-3.8-flash) (`gemini-3.8-flash`) and the Gemini 4 family members [Carbon](https://aistudio.google.com/docs/models/gemini-4-carbon) (`gemini-4-carbon`), [Hydrogen](https://aistudio.google.com/docs/models/gemini-4-hydrogen) (`gemini-4-hydrogen`), and [Neon](https://aistudio.google.com/docs/models/gemini-4-neon) (`gemini-4-neon`). All four support a 1,048,576-token context window, image input, implicit prompt caching, and thinking levels. Gemini 4 Hydrogen and Neon also support the new `xhigh` thinking level, and the Gemini reasoning transform now accepts `xhigh` choices. Flash, Carbon, and Hydrogen are also available on Vertex AI; Neon is not listed there. See the [Gemini](/providers/gemini) and [Vertex AI](/providers/vertex) pages for details and pricing. (thanks @mzakharocsc for reporting!) ([#2067](https://github.com/Zoo-Code-Org/Zoo-Code/issues/2067), [#2640](https://github.com/Zoo-Code-Org/Zoo-Code/pull/2640))

## Responses API Support for OpenAI Compatible Providers

OpenAI Compatible providers now have a per-profile **Use Responses API** setting. When enabled, requests go to the Responses API (`/responses`) instead of Chat Completions (`/chat/completions`). Turn this on for endpoints that require the Responses API to combine reasoning effort with tool use, such as Azure OpenAI deployments of GPT-6.1 Terra. See the [OpenAI Compatible](/providers/openai-compatible) page. ([#1579](https://github.com/Zoo-Code-Org/Zoo-Code/issues/1579), [#2040](https://github.com/Zoo-Code-Org/Zoo-Code/issues/2040), [#2498](https://github.com/Zoo-Code-Org/Zoo-Code/pull/2498))

## Provider Fixes

- **Vertex AI:** Gemini requests that end with a model turn are no longer rejected by Vertex. The shared Gemini handler appends a short user turn to keep the request valid, and the message history is preserved. ([#1287](https://github.com/Zoo-Code-Org/Zoo-Code/issues/1287), [#2641](https://github.com/Zoo-Code-Org/Zoo-Code/pull/2641))
- **LiteLLM:** Tool call ids from LiteLLM are no longer truncated in a way that corrupts Gemini thought signatures. The signature is read from `provider_specific_fields` directly, so follow-up requests no longer fail with `Base64 decoding failed` errors. (thanks @PierrunoYT!) ([#2064](https://github.com/Zoo-Code-Org/Zoo-Code/issues/2064), [#2119](https://github.com/Zoo-Code-Org/Zoo-Code/pull/2119))
- **Ollama:** Native Ollama now fetches model metadata before context management runs, so tasks condense at the model's configured context limit instead of falling back to a 128k default. ([#1151](https://github.com/Zoo-Code-Org/Zoo-Code/issues/1151), [#2520](https://github.com/Zoo-Code-Org/Zoo-Code/pull/2520))
